# Codex QA·검증 체크리스트

## 심각도

| 등급 | 의미 | 예시 |
|---|---|---|
| P0 | 학습 결과를 정반대로 만들거나 데이터 손실 위험이 있음 | 핵심 정리·수식의 결론 오류, 자동화가 노트를 삭제함 |
| P1 | 핵심 학습 흐름 또는 참조가 깨짐 | 존재하지 않는 필수 위키링크, 잘못된 전제에서 이어지는 유도 |
| P2 | 탐색성·일관성·재현성 저하 | 메타데이터 누락, 별칭 충돌, 중복 가능성이 큰 노트 |
| P3 | 선택적 개선 | 표현 통일, 보조 링크 추가 제안 |

## QA 항목

### 1. 구조·탐색

- 내부 위키링크 대상이 실제 노트 또는 등록된 별칭인지 확인한다.
- 같은 개념이 서로 다른 제목으로 중복 생성되었는지 후보만 보고한다.
- MOC에서 핵심 노트로, 핵심 노트에서 상위 MOC로 이동 가능한지 표본 점검한다.
- 제목, 파일명, 별칭이 링크 해석에 충돌하지 않는지 확인한다.

### 2. 메타데이터

- 콘텐츠 노트의 frontmatter가 프로젝트의 해당 노트 유형 규칙을 따르는지 확인한다.
- `subject`, `chapter`, `concept`, `cluster`, `cross_ref`, `moc`, `tags`는 노트 유형에 맞게 검토한다. 모든 노트에 일률적으로 강제하지 않는다.
- 날짜·별칭·태그의 형식 불일치와 중복을 보고한다.

### 3. 통계·코드 교차검증

- 결론보다 가정, 표기, 차원, 등호 변형, 정리 적용 조건을 우선 검증한다.
- 수치 예제는 독립 계산으로 재현한다.
- 코드가 있으면 실행 가능성, 난수 시드, 입력·출력, 패키지 의존성을 확인한다.
- 불확실하거나 교재 판본 의존적인 내용은 단정하지 않고 검증 보류 사유와 확인 자료를 기록한다.

### 4. 수정 검증

- 이슈의 재현 절차와 정확한 수정 대상 파일을 기록한다.
- 최소 변경 원칙을 따른다.
- 수정 뒤 관련 링크 검사·계산·코드 실행을 다시 수행한다.
- 새 오류·미결 이슈는 별도로 적는다.

## 보고서 양식

```markdown
---
date: YYYY-MM-DD
scope: [검토한 경로 또는 노트]
type: [qa | integrity | verification | fix]
status: [pass | issues_found | blocked]
---

# 검토 결과 — [범위]

## 요약
- 대상: ...
- 검사: ...
- 결과: 통과 / 이슈 N건 / 보류

## 이슈

### [P1] 짧은 제목
- 위치: [[노트 제목]] 또는 `상대/경로.md:행`
- 근거: 재현 가능한 사실 또는 계산
- 영향: 학습·탐색·자동화에 미치는 영향
- 권장 조치: 가장 작은 수정안
- 상태: open / fixed / deferred

## 실행한 검증
- 명령 또는 검토 절차: ...
- 결과: ...
```
